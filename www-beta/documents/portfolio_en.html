business content (During the period of 2010-2014, I worked on several tasks at the company, including video streaming service, speech synthesis web API server, and building campaign websites for video and audio synthesis. However, as those were smaller-scale contract developments, I will omit the specific details.)

EXLINK had originally developed a bulk SMS messaging system, but the system had the following issues:
  1. A performance-limited transmission module heavily dependent on jsmpp (Java SMPP library).
  2. Inability to scale due to Java-based ORM (Object-Relational Mapping) tool Hibernate locking all DB tables, resulting in a bottleneck and low throughput.
  3. Outdated administrative GUI with PHP-based HTML generation, both in terms of architecture and appearance.
  4. Low throughput due to the PHP implementation of the public API, requiring frequent database searches with each request.
  5. Lack of CI/CD (Continuous Integration and Continuous Delivery) concept, relying solely on manual intervention and programmer's attention, leading to frequent system failures.
  6. Periodic abnormal throughput degradation caused by Java's Garbage Collection (GC) issue, requiring manual restart of transmission processes.
  7. Decreased throughput with an increase in the number of log records in the database, requiring manual deletion of DB table records by programmers.
I completely redesigned and re-implemented everything from the conceptual design to address those issues.
  1. Improved the performance of the transmission module.
    1. Implemented the raw SMPP communication protocol in C++, achieving multi-process parallelization of submit_sm and deliver_sm message handling, with each SMPP account assigned to a separate process. With this architecture, by increasing the number of SMPP contracts and processes (and potentially virtual machines if needed), the throughput can be significantly increased in proportion, making it highly scalable (the only remaining bottleneck being the database, for which I have an idea).
    2. Implemented a mechanism to move processed DB records to a separate table.
    3. As a result, the throughput has increased tenfold compared to the previous system.
  2. Revamped the administrative interface using the AJAX model.
    1. The server only returns static HTML and JavaScript instead of dynamically generating HTML.
    2. The server processes API commands, which primarily involve communication with the DBMS, result manipulation, and JSON serialization. Implemented using raw PHP without any frameworks.
    3. The client-side implementation utilizes jQuery, Bootstrap, and a modern template.
    4. Customized certain components, such as draggable dialogs, sortable tables using drag and drop, and custom-designed tooltip-like pop-ups, to improve the behavior of pre-existing elements.
  3. I implemented the public API in C++. By caching the data from the database in memory, I was able to increase throughput by several tens of times.
  4. I created three systems for the management screen and transmission module: 'development', 'commercial beta', and 'commercial'. I also created a bash script that displays differences between them, performs updates in dry run mode, and executes actual updates.
    Nowadays, this system is referred to as CI/CD (Continuous Integration and Continuous Delivery), but I don't recall this concept being heavily emphasized at the time.
  5. To achieve the above, I completely redesigned the database table definitions. I also created a script to convert from the old system to the new system's database in bulk.
    In other words, the only thing I reused from the old system was the customer data.
Role All of the above tasks, including the design, implementation, and testing of the transmission module, public API, and DB, were carried out by me alone.
I also created the framework for the GUI and internal API and created generic.html and the php function Generic($args) for use by other programmers.
I had others help me debug and flesh out the contents of the framework, as well as add new features.
